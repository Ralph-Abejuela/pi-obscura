## UI / manual (run through the module runtime path the pi tools call; the literal in pi calls are a spot check)

- [x] In pi, call `browser_read` on a fixture page (data: URL with a button, a text input, a select, a textarea, a link) → the refs list the elements; an input ref now names its type and a select ref lists its option values. (Ran in pi: refs `[1] search`, `[2] button "Go"`, `[3] select (Alpha Beta)`; the self check also asserts the input type and the option pairs.) → AC-2
- [x] Call `browser_click` with a button's ref → the click lands on the button; the result reports the element label, the current URL and title, and fresh refs. (Ran in pi: `Clicked [2] "Go". Now at Interact (...). Scroll at (0, 0).`) → AC-1, AC-2
- [x] Call `browser_click` on a link ref → the page navigates; the result reports the new URL and title and the fresh refs describe the new page. (Ran in pi: `Clicked [1] "next". Now at Second (...)`) → AC-1, AC-2
- [x] Call `browser_click` on a ref whose center another element covers (for example a fixed header overlapping the target) → a plain refusal naming the covering element. → AC-1, AC-7
- [x] Call `browser_click` on a target whose center lands on one of its own descendants (for example a button with a nested span) → the click lands on the button, counted as clear. → AC-1, AC-7
- [x] Call `browser_fill` on a text input ref with a value → the input shows exactly that value (replaced). → AC-3
- [x] Call `browser_type` on the same input ref with more text → the value appends; the fresh read reflects it. → AC-3
- [x] Call `browser_fill` on a checkbox or select ref → a plain refusal naming the kind. The contenteditable half of this step cannot be exercised through the tool: a plain contenteditable region is never a ref (refs are only links, buttons, inputs, selects, and textareas), so that refusal is a guard rather than a reachable path (recorded in the spec's data model sketch). → AC-3, AC-7
- [x] Call `browser_key` with Enter while a submit button is focused → the form submits (or the button's click path fires); the result settles and reports. → AC-4
- [x] Call `browser_key` with Enter plus the submit button's ref → the same submit without a prior type into it. → AC-4
- [x] Call `browser_key` with Tab → the page sees a trusted keydown and focus does NOT move: this engine performs no native focus traversal (probe recorded in the spec rationale, asserted both ways by the self check); with an unknown key name → a plain unknown key refusal; with modifiers → a plain refusal naming the dropped modifier state. → AC-4, AC-7
- [x] Call `browser_choose` on a select ref with an option's label text → matched to its value and the change event fires; with the value attribute → also matched; with a bogus option → a refusal listing the valid labels and values. → AC-5, AC-7
- [x] Call `browser_scroll` with a ref far down the page → the element scrolls into view; call it with a signed amount → the window moves by that amount; both report scrollX and scrollY. → AC-6
- [x] Read, click a link, then pass a ref from before the navigation → a plain stale refusal telling the agent to re read. → AC-2, AC-7

## Commands

- [x] `npx tsc --noEmit` → exits 0. (Run: `npm run typecheck`, exits 0.) → AC-9 (type bound)
- [x] `node node_modules/@earendil-works/pi-coding-agent/node_modules/jiti/lib/jiti-cli.mjs scripts/interaction-selfcheck.ts` → prints "interaction tools self-check passed". The self check proves the search, fill, submit flow, each step asserting fresh refs, plus the refusal cases (stale ref, covered element, fill on a checkbox, choose to a missing option, a modifier argument, an unknown key), and it now also records where a click lands when the cover check cannot see the cover, and that Tab is delivered without moving focus. → AC-1, AC-3, AC-4, AC-5, AC-7, AC-8
- [x] Engine level (run during `/check verify`): kill the engine mid flow and call an action → the action in flight fails in plain words with a next step and no protocol text ("The engine died while the page snapshot was in flight; the page state is gone. The next browser call starts a fresh engine."), that same call raises the death verdict (supervisor phase goes to `dead`), and the very next call serves a fresh blank engine (`title` empty, `refs = 0`): one failed call, then recovery. Two fixes landed here: the engine down pattern gained the transport codes (`ECONNRESET`, `EPIPE`, `ECONNREFUSED`, `ENOTCONN`, `EHOSTUNREACH`), and classification became idempotent, because an action op was re-wrapping the already plain snapshot error into a fresh unmarked one (which also produced the doubled `the click failed: the page snapshot failed:` prefix). (Ran: scratch/verify-engine-death.ts, evidence in scratch/verify-engine-death.txt.) → AC-7, AC-9
